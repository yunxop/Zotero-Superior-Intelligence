# 科研写作知识库（2.0.0）

## 使用步骤

1. 安装 `dist/zotero-superior-intelligence-2.0.0.xpi`，重启 Zotero 10。
2. 在 SI 设置中配置当前 LLM。打开 **SI 文献助手 → 科研写作知识库**。
3. 在 Zotero 选择一篇或多篇文献/PDF，选择“当前选中的文献/PDF”，点击 **读取 Zotero 当前范围**。普通文献使用第一个有本地文件的 PDF；需要处理多个附件时直接多选 PDF。
4. 填写研究主题。填写 Voyage API Key 和模型并保存，默认 `voyage-4-lite`。也可取消语义筛选，仅使用关键词。
5. 设置每篇段落数上限及最低相关性，点击 **开始提取**。默认最多 20 段/篇，按混合相关性排序；不是全文所有证据的穷尽抽取。
6. 查看原文、中文解释、IMRaD 分类、相关性及借鉴价值；打开原文所在页核验，修订提取内容并选择通过、拒绝或待审核。
7. 按状态、类型、章节检索与导出。关键词搜索匹配标题、主题、原句及解释；语义搜索匹配已缓存的来源段落。

## 数据与来源

- `<Zotero 数据目录>/si-writing.sqlite`：独立数据库，保存段落、Embedding、提取结果、审核状态与自动笔记映射。
- `<Zotero 数据目录>/si-writing/knowledge.md`：自动更新的 Markdown 镜像；数据库是权威数据源，手工改 Markdown 不会回写。
- 同目录下 `export-*.md` / `export-*.jsonl`：每次导出的独立快照。
- 密钥保存在 Zotero 本地首选项，与现有 LLM 配置方式一致，不写入知识库和导出。
- 按图书馆、PDF 附件 key、类型、规范化原句去重。重复提取不会覆盖人工审核与修订。同一原句再次用于新主题时，会追加固定 ID 到 `topicIds`，导出的 `topics` 为当前名称列表，首次 `topic` 快照保留；不同论文保留各自来源。审核结果在该记录的多个主题之间共享。
- 记录保留 DOI、作者、日期、标题、页码标签、PDF 实际页码、页内段落编号、来源段落、附件 key、模型、创建/审核时间，以及 `originalDetails` 原始模型字段。
- 源原句须在对应段落中逐字存在（仅规范化空白）；模型生成的解释和证据归纳仍需要人工核查。相关性是关键词/向量相似度评分，不是事实可信度；借鉴价值是模型评分。
- 自动 Zotero 笔记标题为“科研写作知识库 · 研究主题”，按 PDF 与主题更新已有笔记（旧版本生成的无主题标题会在重新提取该主题时更新）；笔记是提取时快照，后续审核在知识库中维护。

## PDF、语义与批处理限制

使用现有 Zotero PDF 阅读器文字坐标接口读取逐页字符。段落依靠 PDF 的段落/换行标记，章节采用英文标题启发式并由 LLM 分类；复杂版式和非常规章节可能需要人工纠正。长段落按约 2800 字符分割，段落编号表示本地解析片段。

扫描 PDF 须先 OCR。当前不使用 MinerU 云端文本替代带页码的原文，以免把无法核验的页码写入知识库。没有文字层的文献会报告失败并继续下一篇。

Voyage 使用官方 HTTPS Embeddings 接口，段落用 `input_type=document`，主题用 `input_type=query`；语义模式采用 30% 关键词 + 70% 非负余弦相似度。仅比较同一模型的向量。更换模型后须重新提取以更新索引；未索引或模型不匹配的旧记录只能贡献关键词分数。当前向量检索在内存计算，适合个人库，不使用向量数据库扩展。

任务按文献串行，LLM 每组最多 4 个段落；单篇错误不会阻断后续文献。已完成分组立即存储。关闭窗口任务继续；停止/退出 Zotero 中止后续操作，已存结果保留。重新执行会复用相同原文的 Embedding 并对记录去重，但会重新请求 LLM，不是持久化的精确分组断点续跑。

点击开始会发送 PDF 段落到 Voyage（勾选语义时）及筛选后的段落到 SI 当前 LLM；语义搜索仅发送搜索词。请求可能产生服务商费用，失败后不自动无限重试。

## Agent 与微调导出

**Agent JSONL** 每行一条结构化记录，包含 `schemaVersion: 1`、`id`、`kind`、`quote`、`details`、`originalDetails`、`source`、`status` 等，Agent 可直接读取文件作为带来源的 RAG 材料。默认包括待审核记录，正式使用可先筛选“已通过”。这是文件/进程内接口，不包含新建 MCP HTTP 服务。

**微调 JSONL** 只导出 `approved` 记录，采用 `{messages: [{role, content}, ...]}` 格式。输入包含主题与原句，输出为人工确认的结构化分析；实际训练前按目标服务商要求进行格式及数据适用性检查。没有自动启动模型训练。

**Markdown** 为可读语料/证据卡片。三个导出按钮都应用历史主题、状态、类型和章节筛选，导出全部匹配记录，不受搜索词及分页限制。

Zotero 内已授权的其他插件或 Agent 桥接可以调用：

```javascript
const kb = Zotero.MinerUAI.writingKnowledge;
const result = await kb.search({
  query: 'urban heat', semantic: true,
  status: 'approved', kind: 'evidence', limit: 50, offset: 0
}); // {total, records}
const file = await kb.export('jsonl', {status: 'approved'});
// 返回本地导出文件绝对路径。搜索/导出不修改审核状态。
```

## 历史主题、复制与删除（1.2.1）

提取页面的“历史提取主题”下拉框显示有记录的主题及数量，切换后展示对应句子，可继续结合类型、章节、审核状态或搜索词筛选。新提取结果完成后自动刷新历史主题。主题筛选也作用于三个导出按钮。

每张卡片可以“复制原句”或“复制原句及来源”，也可以勾选本页多条记录再“复制选中原句”，随后粘贴到 Word、笔记等编辑器。

支持单条删除和勾选批量删除。删除记录会从全部关联主题、检索、Markdown 镜像以及后续导出中移除；不会删除原始 PDF、现有 Zotero 笔记或已经导出的文件。采用持久化删除标记，重新提取不会自动复活记录。“撤销上次删除”在当前窗口中恢复最近一次操作及其原审核状态；关闭窗口会清除该按钮的撤销历史；2.0.0 可在主题管理的“记录回收站”中恢复历史删除记录。

审核状态的含义：
- **待审核**：AI 提取结果尚未人工确认。
- **已通过**：人工确认可用，可进入微调数据导出。
- **已拒绝**：保留记录供查看，不进入微调导出；可随时改回待审核或通过。

审核不等于删除。普通 Markdown / Agent JSONL 导出遵循当前筛选；若状态选择“全部”，仍包含已拒绝记录。仅想使用确认过的内容时应筛选“已通过”。审核结果不代表自动事实认证，不会自动训练模型。

## 跨子分类批量提取（1.2.2）

例如 Zotero 左侧分类为：城市气候 → 热岛、绿化、建筑；绿化下还有公园、街道树等子分类。

1. 在 Zotero 左侧点击共同父分类“城市气候”。
2. 打开“科研写作知识库”，提取范围选“当前分类及全部子分类”。
3. 点击“读取 Zotero 当前范围”，检查显示的分类数、去重 PDF 数和无 PDF 跳过数。
4. 输入统一主题，例如“植被缓解城市热岛的证据和英文表达”。
5. 点击“开始提取”，插件按去重后的 PDF 队列逐篇处理；结果在该主题下统一检索、审核和导出。

若想覆盖整个库，范围改为“当前文献库全部论文”。个人库与群组库按当前选中的库隔离。若只处理一些论文，可使用“当前选中的文献/PDF”。

分类范围包含父分类直接归属条目和所有层级子分类条目；同一条目归属多个分类仅处理一次，已删除条目排除。普通文献使用第一个本地 PDF；全库模式不额外遍历每篇的所有附属 PDF。需要读取补充材料时可直接多选对应 PDF，再使用选中条目模式。

读取范围只在本地汇总并固定 PDF 队列，不调用 Voyage/LLM。切换范围后必须重新读取；改变 Zotero 的分类选择后也应重新读取。只有点击开始才发起分析。此功能遍历所选范围的所有有 PDF 的论文，但每篇仍按相关性阈值和段落数上限筛选，不意味着穷尽全文每一条证据。

## 2.0.0 主题管理

点击提取页顶部 **主题管理 / 回收站** 进入独立管理界面。

- 支持搜索名称、别名、说明、标签；按最近使用、更新时间、名称、句子数排序，每页 30 个主题。
- 每个主题显示论文数、语料数、待审核数、文件夹、标签和时间。
- 编辑主题可重命名、修改说明和默认提取指令、设置文件夹路径（最多三级，例如 `城市气候/热岛/植被`）、标签、置顶或归档。
- 提取页面默认只列出置顶和最近使用的 20 个有效主题；输入名称/别名/标签可以查找，也可从管理页选择任意主题。
- 主题名称与指令分开。选已有主题后名称只读，通过管理页改名；本次指令可以单独调整，不覆盖默认指令。新主题开始时自动创建；初次指令作为默认指令。
- 主题合并将源主题记录和历史关联到目标主题，重复记录保留一条，源名称成为目标的别名。源主题隐藏，不能单独恢复；合并前页面有明确确认提示。目标的说明和默认指令不被覆盖。
- 文件夹采用主题上的路径字段，空文件夹不独立保存；标签用于跨文件夹筛选。修改主题文件夹路径即可移动主题。

### 记录整理与回收站

选择具体历史主题并勾选记录后：

- **从本主题移除**：只解除当前主题关联。若不再属于任何主题，记录仍在“全部主题”中，可重新关联。
- **关联到目标主题**：保留原有主题，再增加目标主题。
- **移动到目标主题**：解除当前主题关联，并关联到目标；其他主题关联不受影响。
- **从知识库删除**：记录进入回收站，从所有常规检索与后续导出移除。主题管理 → 记录回收站可逐条恢复，恢复时保留审核结果。
- **移入主题回收站**：仅隐藏主题，不删除共享语料、原文、笔记或已有导出。切换管理页状态为“主题回收站”可恢复；记录仍可在“全部主题”查看。归档只隐藏常用入口，可从“已归档”管理。

整理主题和调整记录关联在提取运行时会被阻止，防止同一批提取途中改变主题归属；完成或主动停止后可操作。

### 迁移与历史

首次打开自动迁移 1.x 主题为固定 ID，所有改名/合并/移动均使用 ID。迁移在事务中执行，并在同一数据库的 `writing_legacy_records` 保存原始记录 JSON；`writing_meta` 保存迁移标记，重复打开不重复迁移。仍建议随 Zotero 数据目录一起备份数据库。旧版本程序不了解 2.0 主题管理结构，不建议在迁移后降级继续写入。

主题管理 → 编辑主题 → **查看提取历史**，可分页查看每批的主题名称快照、提取指令、PDF 条目队列、范围说明、模型、完成/失败/取消状态和记录数。更改主题名称或指令不会改写旧批次快照；合并只调整批次归属。升级前没有保存的批次信息无法补全。退出中断的批次在下次打开标记为“退出中断”，不会自动重新请求收费 API。

旧 Zotero 子笔记内容仍是快照，主题改名不会立即改写已有笔记；下次对同一 PDF 和主题提取时更新已有笔记。合并后的目标主题使用自己的笔记映射，旧源主题笔记保留。

Agent 可调用 `topicList({query, state, folder, tag, sort, offset, limit})`，返回 `{total, topics, folders, tags}`。`search` 和 `export` 支持 `topicId` 筛选。记录新增 `topicIds`，`topic` 保留首次提取名称，`topics` 为当前可见主题名；原有 JSONL 字段仍保留。主题数据与提取批次位于同一 SQLite 的 `writing_topics` / `writing_batches` 表，不启动网络服务。
