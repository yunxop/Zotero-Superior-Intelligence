## 已确认的问题

### 1. P1：章节识别失败会导致正文不被翻译和批注

位置：`paper_annotation.js:36–65`、`:263–299`。

解析器将第一个已识别标题之前的所有文本归入“前置信息”，而 `ancillary()` 又将它全部排除出分析。没有标准标题的短文、标题与正文连在一行的 PDF，可能包含完整英文正文却报“未提取到可用于双栏批注的论文正文”。若后面出现能识别的标题，则只分析后面的部分，前面的正文仅以折叠原文保留。

复现：无标题的两句英文研究正文直接失败；以 `Study area and data` 开头、后面接 `2. Results` 的输入，只分析 Results。另一个相关问题是 `sourceFragment()` 只统计含小写字母的英文词，把 `CO2 AND CH4 EMISSIONS INCREASED BY 20%.` 这样的完整大写句子当成无需翻译的碎片。

建议：明确区分“已确认的元数据”和“未识别章节的正文”；没有标题时以“正文”兜底。生成前显示分析段落数、仅保留原文的段落数和原因；未知文本不应因标题判断而静默跳过。扩展标题和大小写用例。

### 2. P1：中途失败没有检查点，重试会重新处理已完成分组

位置：`paper_annotation.js:289–313`、`:388–401`；`main.js:468–477`。

每组分析只保存在本次调用的内存对象里，所有翻译和总览完成后才保存 HTML。HTML 分支也在普通任务历史创建之前返回。后段网络错误、非法 JSON、总览失败或取消任务，都会使已完成分析无法在下次生成时复用。

复现：让第 2 组模拟失败，再启动生成，第 1 组被再次请求。已有真实 PDF 提取样例需要 **13 组正文分析**，随后还要生成总览；这类任务的重复成本值得优先解决。

建议：复用已有 TaskCheckpointCache，把逐组结果和总览阶段分别保存；缓存身份包含 PDF 内容指纹、提示词、模型和格式版本。接入任务历史、失败组重试和取消后继续。总览失败时允许保留明确标为“未完成”的阅读附件，同时避免把未校验的截断 JSON 当作有效结果。不要通过无条件自动重试增加不透明的 API 费用。

### 3. P2：MinerU 的表格、公式和图片结构没有保留

位置：`paper_annotation.js:36–65`、`:327–380`。

Markdown 在进入生成流程时变成普通字符串：图片语法被替换为替代文本，表格行用空格连接，公式最终按普通文本转义。当前 HTML 渲染器没有表格、图片或数学公式节点。

复现：包含表格、`$$E = mc^2$$`、图片的 Markdown，输出没有 `<table>`、`<img>` 或 KaTeX 结构，图片路径也不再保留。原生 PDF 路径同样没有提取图像/表格结构的步骤。

建议：使用包含 paragraph、heading、table、equation、figure 的中间结构。公式可复用仓库现有离线 KaTeX 能力；只渲染解析器确认的公式，保留原文回退。表格按单元格保留，图片从解析结果的本地资源中验证后内嵌，并相应调整 CSP。不要靠模型重绘数据图或猜测数值。

### 4. P2：跨行断词被错误拼接

位置：`paper_annotation.js:41`、`:70–127`。

当前逻辑把文本行直接用空格连接。`tem-` 换行接 `perature` 会变为 `tem- perature`，影响原文阅读、搜索、翻译及短语匹配。跨页续接仅覆盖少数首尾字符模式，数字或符号开头的续句也需要专项覆盖。

建议：结合 PDF 的断行/断词标记处理软连字符，区分真实复合词与排版断词；保留原始字符与阅读文本之间的映射，避免清理后失去高亮和来源定位。补充双栏、跨页、上标单位、公式相邻段落的提取用例。

### 5. P2：默认打印会遗漏折叠的参考文献等原文

位置：`paper_annotation.js:344–345`；`paper_annotation.css:70–74`。

附属内容放在未展开的 `<details>` 中，打印样式仅隐藏导航并调整颜色，没有展开或提供完整打印视图。

复现：现有样例在 Chrome 打印媒体下，6 个附属原文块全部不可见。该结果验证了打印时的可见性，尚未验证多页打印分页和 Zotero 内置阅读器打印。

建议：提供明确的完整打印视图，确保参考文献和来源信息可打印；对长段落与长表格允许合理分页，并在 Chrome 和 Zotero 使用的实际引擎中验收。

## 对阅读质量影响较大的设计改进

1. **给每段保留来源定位。** 当前 `cleanPDF()` 将多页变为字符串，随后仅保留章节和文字，HTML 没有 PDF 页码、附件键或段落来源链接。建议在提取阶段保留物理页码、显示页码、段落 ID 和必要坐标，提供“回到 PDF 原文”。跨页段落保留多个来源范围；OCR 缺少页码时明确标记，不能推测。
2. **让批注有足够的论证上下文。** `generate()` 每次只给模型标题、截断后的目录和当前约 3200 字符分组。长段落按约 2000 字符切分，缺少相邻段落和全文研究背景。建议先建立简短的全文论证提纲，再提供相邻段落摘要与术语表，最后对同一原段的分片批注去重合并。
3. **总览保留具体事实和证据 ID。** 目前总览输入只包含“段落功能、逻辑角色、评价、少量高亮短语”，没有完整译文或独立的事实摘要；高亮允许为空。它可能缺少写总览所需的具体数据。建议每段单独提取事实、限定条件和证据引用，总览中的主张能点击返回对应段落。明确区分作者结论、模型解释与待核实判断。
4. **提供适合长时间阅读的控制。** 保留双栏布局，增加原文/译文显示切换、字号和栏宽设置、批注折叠、可收起的层级目录与当前章节提示。现有横向目录在章节多时难以浏览；手机上一个长段落需要滚动多屏才能看到对应批注。交互方案需同时适配离线文件、CSP 与 Zotero 阅读器。
5. **在 HTML 保留可复现元信息。** 标注论文作者/年份/DOI、生成时间、模型名、插件与格式版本、提取方式、覆盖率和完成状态。避免保存 API Key 等凭证。可一并保存校验后的结构化结果，使更换排版不必再次调用模型。

## 建议实施顺序与验收

| 顺序 | 工作 | 验收标准 |
| --- | --- | --- |
| 第一轮 | 正文兜底、大小写误判、任务检查点、来源信息 | 无标题短文可完整分析；第 N 组失败后前 N−1 组不重复请求；每个可分析段落能定位来源或说明定位不可用 |
| 第二轮 | 图表/公式中间结构、断词与跨页恢复、完整打印 | Markdown 表格和公式不再退化；图片可离线打开；打印内容覆盖附属原文；清理前后来源映射可验证 |
| 第三轮 | 全文上下文、证据链接总览、阅读控制 | 长段落分片不产生重复批注；总览主张有证据跳转；桌面/窄屏/离线/Zotero 内均完成验收 |

通用工程小项：`paper_annotation.css:37–40` 有两组完全重复规则，可在下一次样式修改时清理；README 的“24 个测试脚本”已落后于当前 25 个；HTML 分析测试应加入上述异常输入，浏览器测试应显式记录未执行原因，避免“跳过”被误读为完整通过。现有 UI 测试会更新受 Git 跟踪的预览截图，日常验证宜将产物写到 scratch 或临时目录。

## 后续实施：第一轮改进

用户确认继续后，已在工作区落实以下改动（尚未发布）：

- 未识别章节的内容使用“正文”兜底；完整大写英文句子不再仅因大小写被判为公式碎片。
- 段落保留实际 PDF 页码和显示页标，跨页段落可关联多个页面；HTML 提供个人库/群组库的 PDF 链接。没有来源页码的 OCR 内容显示“页码未定位”。
- HTML 显示翻译段落数、仅保留原文的内容数量与原因、可定位阅读块数量、生成时间和模型名。
- 正文分组、总览压缩阶段和最终总览分别保存检查点；只缓存通过结构和高亮范围校验的完整结果，取消后的迟到响应不会进入缓存。
- 检查点身份覆盖提取后的完整文本与页码结构、论文标题、提示词、模型/API 地址/配置槽、思考设置、输出上限和格式版本；凭证不保存到检查点。改变分析输入会重新生成。
- HTML 任务进入持久化任务历史，失败/暂停后可继续；历史记录绑定实际处理的 PDF，完成记录可打开 HTML。相同配置复用仍可用的附件，附件删除、文件缺失或归属变化时从缓存结果重新保存。
- 同一 PDF 的并发 HTML 任务会被阻止，异常后释放锁。磁盘写入失败时提示重启后可能无法续跑。
- 清理重复样式；修复回归中发现的用量日历重建单元格后偶发不重新居中，并把该测试改为同一帧内隐藏/重建/显示的确定性用例。

新增 `tests/paper_annotation_resume.js`，并扩充 HTML 浏览器、任务历史及后台取消测试。开发版共有 26 个测试脚本。此次验证使用模拟模型与存储环境；真实 Zotero 阅读器中的外部协议跳转、真实 LLM 和 MinerU 联调仍需验证。

限制：继续任务仍会重新提取 PDF，扫描件可能再次调用 MinerU；已保存检查点遵循既有的 40 项、30 天、8 MiB 总容量限制。图表/公式结构化、断词恢复、完整打印视图和证据链接总览留待后续阶段，本次未宣称这些问题已解决。

## 后续实施：第二轮改进

- 新增 `paper_content.js`，将解析结果中的表格、独立公式、代码和图片标记与普通段落分开保留。Markdown 表格保留所有数据列；常见 HTML 表格保留行列及 rowspan/colspan，过滤事件、样式和可执行标签。表格不经模型重写数值。
- 正文、译文和表格中的 TeX 使用本地 KaTeX；源文高亮不会切开公式，模型请求分组也避开公式内部。语法不支持时保留可读原式，不执行信任命令或加载外部资源。构建时生成内嵌 WOFF2 的离线样式，含公式的 HTML 才嵌入该样式。
- 断词整理只直接恢复明确的软连字符。普通断词需在同一份原文中找到完整拼写才去掉连字符；无法确认时仅去除连字符后的换行空格，保留复合词连接。TeX 不参与断词改写；整理前文本可展开核对，页码映射继续保留。
- 屏幕仍可折叠附属内容，打印使用独立的完整内容视图，不依赖浏览器对关闭的 details 元素的打印行为。打印时正文、译文、批注按阅读顺序排列，长段落允许跨页，表格重复表头。窄屏宽表格在自身区域滚动。

验证：27 个脚本全部通过；新增专项测试覆盖结构、安全转义、公式、字体、断词、来源与打印。Chrome 实际输出的 3 页样例 PDF 中参考文献标记恰好出现一次，额外数据列与参考文献表格均存在；另一个 5 页长表格 PDF 的 80 个数据行标记各出现一次，表头重复 4 次。桌面、375px 窄屏和打印页已查看。

第二轮的范围限制：这些排版能力依赖提取结果已有 Markdown/HTML 表格或 TeX。原生 PDF 文字坐标路径不会自动重建复杂表格或数学结构；图片保留原始标记并提示回到 PDF 查看，尚未下载/内嵌 MinerU 图像资源。仍未调用真实模型/MinerU，也未进行本轮真实 Zotero/Gecko 打印联调。证据链接总览、全文上下文和阅读控制尚未实施。
